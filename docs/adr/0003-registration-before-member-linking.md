# ADR 0003: 회원 연결 전 반려동물 등록·목록 조회·수정

- 상태: 채택, 무인증 등록·소유자 미연결 동물 목록과 수정 범위에 한정한 임시 결정. 인증된 등록과 상세 조회는 이슈 #11 추가 결정을 따른다.
- 날짜: 2026-11-23 (목록 결정 추가: 2026-11-24, 수정 결정 추가: 2026-11-25)
- 관련 작업: [이슈 #5](https://github.com/louie-kury/louie-kury-pet-service/issues/5), [이슈 #9](https://github.com/louie-kury/louie-kury-pet-service/issues/9), [이슈 #12](https://github.com/louie-kury/louie-kury-pet-service/issues/12)

## 배경

회원가입·로그인·사용자 기능이 아직 없습니다. 사용자는 해당 기능이 만들어지면 연결 작업을 다시 하고 지금은 반려동물 등록만 구현하도록 요청했습니다. 이후 이슈 #5 내용대로 구현을 승인했습니다.

## 결정

- 토큰이 없는 `POST /api/pets`는 현재 인증 없이 허용하고 `caregiverId`를 null로 저장합니다. 인증된 등록은 아래 이슈 #11 추가 결정을 따릅니다.
- 가짜 고정 사용자나 요청 본문·임의 헤더의 사용자 ID를 소유자로 사용하지 않습니다.
- 프로필 미디어가 없으면 정상 등록하며, 값이 있으면 실제 검증·연결 계약이 준비되기 전 저장 없이 503으로 거부합니다.
- 외부 부작용이 없는 등록을 단일 MongoDB insert로 처리합니다. 중간 처리 상태·임대·복구 서비스는 이번에 만들지 않습니다.
- 선택적인 재시도 키가 중복되면 입력과 관계없이 409로 거부하고 기존 응답·동물 ID는 공개하지 않습니다. 무인증 상태에서 다른 등록자의 결과 재전달을 피하기 위한 임시 계약입니다.

## 목록 조회의 추가 결정 (이슈 #9)

회원·인증 연동은 후속으로 두고 목록을 먼저 구현하도록 사용자가 확정한 임시 결정입니다. 기존 등록의 무인증 허용을 자동 확대하지 않고 목록의 공개 범위를 아래와 같이 별도로 정합니다.

- `GET /api/pets`는 인증 없이 누구나 조회할 수 있는 소유자 미연결 동물의 목록입니다. 본인 전용 목록이나 소유권 검증을 제공하는 API가 아닙니다.
- `caregiverId`가 null 또는 미존재이고 `deletedAt`이 null 또는 미존재인 동물만 목록과 건수에 포함합니다. 지정된 소유자가 있거나 삭제된 동물은 제외합니다. 임의 사용자 ID·헤더를 신뢰하거나 고정 사용자를 도입하지 않습니다.
- 기본 `page=0`, `size=4`, 최대 size 100으로 페이지 조회하며 `createdAt DESC, _id DESC`로 정렬합니다. 목록 조회용 복합 인덱스는 기존 이력을 수정하지 않고 새 마이그레이션으로 추가합니다.
- 등록 키 중복 응답은 계속 409이며 기존 결과를 재전달하지 않습니다. 다만 이번에 별도로 허용한 공개 목록에서는 미연결 동물의 ID와 요약 정보가 누구에게나 표시됩니다.
- 나이는 조회 시점의 한국날짜로 다시 계산합니다. 품종명은 현재 기준 데이터로 표시하고, 사라진 품종은 등록 당시 저장한 일치 ID의 품종명으로 보완합니다.
- 프로필 미연결 데이터는 null로 반환합니다. 미디어 ID가 있는 항목은 실제 연결 계약이 준비될 때까지 503으로 거부합니다. DB 실패를 빈 목록으로 숨기지 않습니다.

## 수정의 추가 결정 (이슈 #12)

회원·인증 연결 전 개발 환경에서 단순 CRUD를 진행하도록 사용자가 요청한 별도 임시 결정입니다.

- `PATCH /api/pets/{petId}`는 기본적으로 비활성화되며 Spring `dev` 프로필과 `pet.anonymous-update.enabled=true`를 모두 지정한 경우에만 활성화됩니다. 활성화 시 인증 없이 소유자 미연결·미삭제 동물을 수정합니다. 소유자가 연결됐거나 삭제된 동물과 없는 ID는 404로 처리하며 임의의 사용자 ID를 신뢰하지 않습니다.
- 이 설정은 인증이나 네트워크 격리가 아닙니다. ID를 아는 다른 사람도 수정할 수 있으므로 테스트 데이터와 접근이 제한된 개발 환경에서만 사용하고 실제 사용자 데이터나 외부 공개 환경에는 사용하지 않습니다. 부분 수정에서 생략은 유지, 선택값의 null은 해제를 뜻합니다. 검증 실패 시 저장하지 않고 등록 키와 등록 응답 스냅샷을 보존합니다.
- 미디어 연동 전 수정 후 프로필 ID가 남으면 503으로 거부합니다. 인증 도입 시 무인증 예외를 제거하고 검증된 주체의 소유권을 확인합니다.

## 영향과 후속 작업

[ADR 0001](0001-storage-and-layer-boundaries.md)의 미정 인증 연동 부분에 대해 위 등록·목록·수정 범위에만 임시 결정을 적용합니다. 다른 서비스나 상세 조회·삭제 API의 무인증 허용을 뜻하지 않습니다. 이 임시 결정이 인증된 상세 조회의 소유권 검증을 의미하지는 않습니다.

인증된 목록과 수정의 소유권 검사, 사용자별 재시도 scope는 별도로 구현합니다. 기존 null 소유자의 귀속에는 별도 증명·이관 정책이 필요하며 최초 로그인 사용자에게 자동 부여하지 않습니다. 미디어 연결은 실제 내부 계약 및 부분 실패 처리와 함께 후속 구현합니다.

이 ADR은 결정 기록입니다. 이번 목록 API와 새 인덱스는 테스트용 MongoDB에서 확인했고 실행 서버에서 등록·목록·페이지 조회를 확인했습니다. 인증·미디어 서비스 연동은 검증하지 않았습니다.

## 코드 컨벤션 적용 시 트랜잭션 예외 (이슈 #7)

등록은 하나의 MongoDB 문서에 데이터와 응답 스냅샷을 단일 insert로 저장하며 중복은 고유 인덱스가 제어합니다. 여러 쓰기를 하나의 트랜잭션으로 묶을 필요가 없고 이 서비스는 JPA와 MongoDB를 함께 사용하므로, 쓰기 서비스에 무조건 `@Transactional`을 적용하는 공통 규칙의 예외로 유지합니다. 현재 별도의 Mongo 트랜잭션 매니저는 설정하지 않았습니다. 향후 여러 문서 쓰기나 외부 부작용이 추가되면 MongoDB 실행 환경과 트랜잭션 매니저를 지정하여 원자성 경계를 다시 설계해야 합니다.

## 인증된 등록과 상세 조회 추가 (이슈 #11)

- 인증 서비스가 발급한 Bearer JWT를 반려동물 서비스가 신뢰하는 JWKS로 직접 검증하고 토큰의 회원 식별자를 사용합니다. 게이트웨이의 토큰 검증도 필요하며 별도 연동 대상입니다.
- 등록 요청에 유효한 토큰이 있으면 회원 식별자를 `caregiverId`로 저장합니다. 토큰이 없는 기존 임시 등록은 그대로 유지하며, 유효하지 않은 토큰은 거부합니다. 기존 등록 키는 인증 여부와 관계없이 전역으로 중복을 거부합니다.
- 상세 조회는 인증된 본인 소유이고 삭제되지 않은 동물만 허용합니다. 기존 미연결 동물은 자동 귀속하지 않습니다. 목록과 수정의 기존 임시 동작은 그대로이므로 회원이 연결된 동물을 목록에서 보여주거나 수정할 수 없습니다.
- 인증 서비스·게이트웨이 실제 연동과 미디어 조회는 별도 검증이 필요합니다.
