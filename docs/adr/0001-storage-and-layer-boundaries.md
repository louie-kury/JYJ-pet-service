# ADR 0001: 반려동물 서비스의 저장소와 계층 경계

- 상태: 채택
- 날짜: 2026-11-20
- 관련 작업: [이슈 #1](https://github.com/louie-kury/louie-kury-pet-service/issues/1)

## 배경

사용자는 이 서비스에서 접종명 테이블만 MySQL로 관리하고 나머지 데이터는 MongoDB로 관리하기로 확정했다. 이는 공통 ERD·반려동물·예방접종 API의 저장소 경계와 일치한다. 분리 이유는 사용자가 별도로 설명하지 않았으므로 추가하지 않는다.

## 결정

- MySQL 8.4.13/JPA와 MongoDB Atlas 8.0.39 연결 기반을 함께 구성한다. 개발 Atlas 클러스터는 `louie-kury-dev`, DB 이름은 `louie_kury_pet_dev`로 설정한다.
- 접종명 기준 데이터는 MySQL, 반려동물 기본 정보·소유 관계·종/품종·접종 이력 등 나머지 이 서비스 데이터는 MongoDB에 둔다. 다른 서비스의 DB 선택은 변경하지 않는다.
- `shared.exception`의 업무 예외·오류 코드는 Spring·HTTP·영속성 기술에 의존하지 않는다. 웹 응답·HTTP 오류 변환과 영속성 공통 코드는 `global`에 두며 내부 도메인에서 참조하지 않는다.
- JPA `BaseEntity`와 MongoDB `BaseDocument`는 각 어댑터의 생성·수정·삭제 시각 기반이다. 내부 도메인 모델이나 HTTP 응답 모델로 그대로 노출하지 않는다.
- 로그인·토큰 검증은 다른 팀원의 별도 MSA가 담당한다. 업무 API 연동 전에 인증 주체 전달·서비스 신뢰 경계·401/403 책임을 합의한다. 임의 요청 헤더 신뢰나 무인증 허용 정책은 이 결정에 포함하지 않는다.

## 영향과 한계

양쪽 DB를 위한 연결 환경변수가 필요하다. DB 접근 비밀값은 코드·문서에 저장하지 않는다. 이번 작업은 로컬 실행 기반이며 업무 스키마, 저장소 간 조회·트랜잭션·이관, 반려동물 CRUD와 배포는 포함하지 않는다. 감사 기반 클래스는 삭제 권한이나 삭제 데이터 조회 제외를 자동으로 보장하지 않는다.

사용자의 Atlas 수동 접속·쓰기·읽기 성공 보고는 신규 서비스의 저장·조회·감사 기능 검증과 구분한다. 실제 DB별 검증 결과나 미실행 사유는 README에 기록한다.
