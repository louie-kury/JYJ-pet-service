# 종·품종 기준 데이터의 MySQL 전환

## 결정

종·품종 기준 데이터는 MySQL `species`, `breed`를 사용한다. 반려동물 본체는 MongoDB에 두고 MySQL의 종·품종 UUID를 문자열로 참조한다. 강아지·고양이 enum은 제거한다. 품종의 소프트 삭제나 활성 상태 컬럼은 추가하지 않는다.

## 기존 데이터

과거 MongoDB `pet_species`와 반려동물의 종·품종 ID는 UUID가 아닐 수 있다. 이관 도구는 기존 ID에서 재현 가능한 UUID를 생성하고 MySQL 기준 데이터와 MongoDB 본문·등록 스냅샷의 참조를 함께 전환한다. MongoDB의 과거 종·품종 문서는 삭제하지 않는다. 과거 활성 여부는 새 기준 데이터에서 사용하지 않으므로 비활성 품종도 이관 후 선택 가능해진다.

기존 MySQL 기준 데이터가 생성된 UUID 또는 이름과 충돌하거나 참조 품종이 과거 카탈로그에 없으면 추측하여 덮어쓰지 않고 중단한다. 실행 전 서비스 쓰기를 중단하고 두 저장소를 백업해야 한다. 두 DB에 걸친 원자적 트랜잭션은 없으며 MySQL이 먼저 커밋된다. 중단 후에는 원인을 해결하고 같은 도구를 재실행한다. 기존 클라이언트도 `dog`·`cat` 대신 이관된 종 UUID를 사용해야 한다.

이 결정은 종·품종을 MongoDB에 둔 ADR 0001과 enum으로 종을 사용한 ADR 0003의 해당 부분을 대체한다. 공통 PRD·API 문서의 저장소 설명은 별도 동기화가 필요하다.
